# Nippo — macOS 工作助手 设计文档

日期:2026-07-10
状态:已定稿(用户确认)

## 1. 目标

一个常驻菜单栏的 macOS 原生应用,帮助用户(在日企工作,报告用日语)完成四件事:

1. 记录工作痕迹(随手记、日历日程、会议纪要),每天自动生成日语**日報**草稿
2. 每周五生成**週振り返り**,每月末生成**月発表**底稿(均为 Markdown)
3. 半自动**打卡**(バクラク勤怠):提醒 + 一键打刻,绝不无人值守打刻
4. 类 Circleback 的**会议记录**:录音 → 本地转写 → AI 纪要

## 2. 关键决策(与用户确认过)

| 决策点 | 结论 |
|---|---|
| 应用形态 | 原生 Swift/SwiftUI 菜单栏应用,SPM 构建(无需完整 Xcode) |
| 文案生成 | **只用 Claude Code CLI 无头模式**(`claude -p`),用现有订阅;不装 Ollama |
| 语音转写 | 完全本地:优先 macOS 26 SpeechAnalyzer,备选 WhisperKit |
| 打卡方式 | 半自动:通知 + 用户点击确认 → 后台 WebView 代点打刻按钮 |
| 勤怠系统 | バクラク勤怠(网页版);用户在内嵌 WebView 手动登录一次,此后复用会话 |
| 报告语言 | 日语 |
| 报告输出 | 本地 Markdown 文件(`~/Documents/日報/` 按年月归档);月発表不做 slides |
| 会议场景 | 线上会议(Zoom/Meet/Teams);双轨录音区分自分/相手 |
| 隐私原则 | 录音与转写不出本机;仅生成文案时把文字素材发送给 Claude;打卡仅访问バクラク勤怠 |

## 3. 整体架构

```
┌─────────────────────────── Nippo.app (菜单栏常驻) ───────────────────────────┐
│                                                                              │
│  UI 层      菜单栏下拉 / 随手记悬浮窗(全局快捷键) / 设置窗 / 搜索回顾窗       │
│                                                                              │
│  服务层     NotesService      随手记增删改查                                  │
│             CalendarService   EventKit 读日程、会议前提醒                      │
│             RecorderService   ScreenCaptureKit+麦克风 双轨录音                 │
│             TranscribeService SpeechAnalyzer / WhisperKit 本地转写            │
│             ReportService     组装素材 → 调 Claude CLI → 写 Markdown          │
│             PunchService      バクラク勤怠 WebView 自动化、漏打检知            │
│             ScheduleService   定时任务、节假日/请假日静默                      │
│                                                                              │
│  数据层     SQLite(随手记、纪要索引、打刻记录、请假日)                        │
│             文件(录音 .m4a / 转写稿 .txt / 报告 .md)                         │
│                                                                              │
│  外部依赖   claude CLI(生成文案) / バクラク勤怠网页(打刻) / macOS 日历      │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 登录自启(SMAppService Login Item)。
- 所有定时行为先过 `ScheduleService.isQuietDay()`:周末、日本法定节假日(内置年历数据,可随版本更新)、用户标记的请假日 → 全静默(不提醒打卡、不生成日报、不提醒会议)。

## 4. 数据存储

```
~/Documents/日報/
├── nippo.sqlite              # 随手记、索引、打刻记录、设置外的结构化数据
├── recordings/2026/07/       # 会议录音(双轨 m4a)
├── transcripts/2026/07/      # 转写稿
└── reports/2026/07/
    ├── 2026-07-10-日報.md
    ├── 2026-W28-週振り返り.md
    └── 2026-07-月発表.md
```

放在 `~/Documents` 下即默认进入 Time Machine / iCloud 备份范围。バクラク勤怠凭据不落盘:登录会话由 WKWebView 持久化 store 保管,不保存明文密码。

## 5. 模块设计

### 5.1 随手记(一期)

- 全局快捷键(默认 ⌥⌘N;**自定义顺延中**,一期固定,见 phase1 计划「后续」——2026-07-10 终極監査时补记)呼出悬浮输入框;回车保存,Esc 取消,不打断当前工作。
- 菜单栏下拉显示当天记录,可编辑/删除。

### 5.2 日历联动(一期)

- EventKit 读取系统日历(Google 日历经系统订阅一并可读);首次使用引导授权。
- 会议开始前 N 分钟(默认 5,可调)通知提醒;三期后通知带「録音を開始」按钮,点击即带日程标题开录。
- **一键入会**(2026-07-10 追加):从日程的 URL/场所/备注提取会议链接(Meet/Zoom/Teams/Webex),
  提醒通知点击或「参加」按钮直接打开;菜单栏面板显示「今日の会議」列表(MeetingBar 式),每条可点击入会,已结束的置灰。
- 当天日程(标题、时间、参会人)自动进入日报素材;有纪要的会议自动关联。

### 5.3 日报生成(一期)

- 工作日设定时间(默认 17:45)自动触发,也可随时手动生成。
- 素材 = 当天随手记 + 当天日程 + 当天会议纪要(三期后)。
- 生成方式:组装 prompt → `claude -p`(无头模式,禁用工具,纯文本生成)→ 写入
  `reports/YYYY/MM/YYYY-MM-DD-日報.md` → 通知用户审阅。
- **生成规则与流水线**(2026-07-10 追加,详见 `docs/nippo-report-rules.md`):esa Markdown 常体格式
  (Today's Focus / 01 今日のこと / 02 判断と進めかた / 03 学び / 04 明日),事实忠实为最高优先级
  (唯一根据=当日素材,禁止补写/夸大/确度升级/代人断定),谦虚语气(禁自夸动词),评价信号从事实渗出;
  生成为四阶段:起草 → 三视角对抗 review(日语自然度/谦虚语气/事实忠实)→ 回源验证合并
  (review 指摘须对照素材验证后才采纳)→ 输出含标题候选与「要確認」块。
- 日报模板可在设置中编辑,默认为上述 esa 五节结构;用户可粘贴公司固定格式。
- 异常处理:
  - `claude` CLI 不可用/断网 → 保留素材,通知「后で再生成できます」,联网后菜单一键补生成;
  - 当天无任何素材 → 跳过并提醒;
  - 目标文件已存在 → 生成为 `-v2` 副本,不覆盖用户改过的稿子。

### 5.4 打卡(二期)

**菜单门禁 UX(2026-07-10 用户指定)**:工作日**未打刻期间,菜单面板本体就是打刻界面**
(内嵌持久会话的バクラク勤怠 WKWebView,用户在页面里点打刻 → 按「出勤打刻した」确认记录);
打刻完成后菜单才切换为正常面板(日程/待办/memo)。配「他で打刻済み」(手机/IC 卡已打,
记录外部打刻)与「今日はスキップ」(仅当次会话跳过)两个逃生口。静默日(周末/节假日/休暇)
不设门禁。打刻状态记录在本地 DB(punch_record)。傍晚退勤提醒与 21:00 漏打再提醒,
通知点击直接打开打刻窗口。自动 JS 代点按钮属后续增强(需真实页面结构),红线不变:
**任何情况下不在用户未确认时记录/执行打刻**。

- 内嵌持久化 WKWebView,用户手动登录バクラク勤怠一次(兼容 SSO/二步验证),会话长期保持。
- 触发:工作日早上首次解锁屏幕 → 出勤提醒;设定时间(默认 18:30)→ 退勤提醒。
- 用户点击通知的「打刻する」→ 后台 WebView 执行 JS 点击对应打刻按钮 → 通知成功/失败。
- **失败回退**:页面结构变化、会话过期等任何异常 → 打开可见窗口让用户手点,并提示重新登录。
- **漏打检知**:早 10:00 / 晚 21:00(可调)仍无本应用经手的打刻记录 → 二次提醒;提醒带「打刻済み」按钮供用户消除(在别处已打的场合)。
- 安全红线:任何情况下不在用户未点击确认时打刻。

### 5.5 会议记录(三期)

**2026-07-10 深夜确认的分路线**(三期 A/B 均已实装,待真机手动验证):
- **三期 A(字幕轻路线,先做)**:不录音、零音频。用户在 Google Meet 手动开字幕,
  一个 Chrome 扩展(仿公司 meet-dictionary)读字幕 DOM(多选择器容错+滚动增量提取)
  +说话人名 → POST 到 Nippo 本地 `127.0.0.1` 监听端口(Network 框架,绝不出网)→
  逐行存转写稿。会议结束用户点「議事録を作成」→ Claude 离线生成
  「決定事項/TODO/議論の要点」→ 存档 `transcripts/` 与 `minutes/` + 自动进当天日报素材。
  合规风险低(只读屏幕已显示的字幕,不采集音频)。
- **三期 B(录音重路线,后续)**:双轨录音+本地转写。**录音前必须勾选确认门**
  「已告知参会者并符合公司规定」;录音中菜单栏变色+屏幕常驻「録音中」标识提醒**用户自己**;
  应用**无法**向会议对方广播录音状态,告知对方需用户亲口进行。红线:未勾选确认不录。

- 菜单栏一键开始/停止;进行中图标变色并显示时长。
- ScreenCaptureKit 抓系统音频(相手)+ AVAudioEngine 抓麦克风(自分),双轨分存 → 无需声纹识别即可区分说话方。
- 转写:优先 SpeechAnalyzer(macOS 26 内置、日语良好、快),备选 WhisperKit(large-v3-turbo);全本地。
- 纪要:转写稿(带自分/相手标记)→ Claude CLI → 「決定事項 / TODO / 議論の要点」日语纪要 Markdown;自动关联当天日程并进入日报素材。
- 检测到 Zoom/Meet/Teams 前台运行且日历有进行中会议 → 弹「録音しますか?」提醒(**不自动开录**)。
- 录音提示 UI 常驻显眼位置;文档与 UI 提醒用户遵守公司规定、告知参会者。

### 5.6 週振り返り / 月発表 / 搜索回顾(四期)

- 周五傍晚:本周日报 → Claude CLI → 週振り返り(默认 KPT 模板,可改)。
- 月末最终工作日:当月日报+週振り返り → 月発表底稿 Markdown(结构:成果 / 数字 / 学び / 来月の計画,可改模板)。
- 搜索/回顾窗口:SQLite FTS 全文搜索随手记、纪要、报告;按日/周/月时间线浏览。

## 9. 非目标(明确不做)

- 全自动无人打刻(合规风险)。**2026-07-10 深夜用户曾要求「打卡后 9.5h 自动退勤」,经确认维持红线不做**
  ——替代实装:+9.5h 弹带操作按钮的通知(勤怠ページを開く/退勤済みとして記録),
  记录退勤时自动打开工数入力页(kousuURL 设置)。摩擦=一次点击,记录仍由用户确认
- 云同步/多设备
- 月発表 slides 自动生成(只出 Markdown 底稿)
- Slack/Notion 集成、Windows 支持
- 会議予習卡片、フォーカス宣言(时间跟踪)、勤怠×日报联动(2026-07-10 用户明确不要)
- 日报素材的 memo 带时间戳(2026-07-10 移除)
- 日報・週報の「無駄話」栏目(2026-07-10 用户明确不要,AI 也不收录)

## 9.5 运行行为决定(2026-07-10 用户指定)

- **开机自动启动默认开启**:首次启动自动注册 SMAppService 登录项(一次性标记 autoLaunchApplied,
  用户在系统设置手动关闭后不强行重开);设置开关保留作状态显示。
- **每天 0 点自动重置 memo**:日期变更 tick(及错过 0 点后的首次启动)删除今天之前的随手记,
  **但仅限「当日日报文件已生成」的日子**(2026-07-10 终極監査 critical 修正:日报未生成的日子
  memo 保留作素材,防止生成失败导致的数据永久丢失)。週報/1on1/学び摘要均只依赖日报文件。

## 10. 追加采纳的功能(2026-07-10 第二轮,待设计细化)

用户确认采纳,按价值排序:

1. **日本語アシスタント**:全局快捷键对选中文字做日语润色(敬语级别可选)与中→日转换,
   转换时套用公司 Notion 用语集的正式说法。走 Claude CLI。
2. **今日のチェックリスト**:每天自动生成当日待办清单,素材=昨日日报的「04 ／ 明日」+
   当天会议内容(三期后含纪要 TODO)+ 未完成的历史项;可勾选,完成状态回流当日日报素材。
3. **截图自动整理**:监视截图,AI 起日语描述性文件名并归档,方便拖进 esa。
4. **1on1 助手**:检测「1on1」日程,会前汇总本周记录成 talking points,会后弹
   「メンターに何を言われた?」快速记录,直接成为日报「学び」素材。
5. **「初めて聞いた言葉」ログ**(依赖三期):转写中出现的用语集外新词攒成个人生词卡。
6. **ブログ支援**(2026-07-10 追加):支撑 Goodpatch Blog 月刊連載「◯月話題になったアプリ、
   サービス、デザインまとめ」。规则源=`~/gp blog/`(CLAUDE.md + reference/ 四文件,**运行时读取
   不复制**,团队更新即生效)。两个能力:
   - **トピックハンター**:**仅菜单按钮手动触发,不自动运行**(2026-07-10 用户明确);Claude CLI **开放 WebSearch/WebFetch**
     (蓝本 CLAUDE.md 本就要求联网裏取り)。**隐私边界的准确表述**(2026-07-10 终审修正):
     prompt 内容送达 Anthropic 这一点与日报生成相同;research 模式的差异仅在于允许 Web 工具。
     由于找题 prompt 含用户日报的「学び」摘要,prompt 内置硬约束:**检索查询禁止包含学び中的
     固有名词/社名/客户名/案件名**,学び只作选题灵感,检索一律用一般性设计用语。
     信源=外部设计圈信息+**用户自己日报的「学び」积累**(优先,「自分の実践から書けるテーマ」)。产出=候补清单(话题/why now/一次情报链接/类别/设计切入点)。
   - **1条ドラフト**:选题→一次情报裏取り(与被交付的摘要有出入时**不写入**,放「要確認」)→
     按 tonmana 起草(400〜500字/3〜4段/です・ます/転換句・結び・語彙噛み砕き规则)→
     对抗 review(tonmana 适合度/事实忠实=一次情报照合/checklist 全项)→ 合并 →
     草稿存 `~/gp blog/outputs/drafts/`,附 要確認 与「他の条と並べて読む」提示。
   - 注意:日报文体(常体・簡潔)与 blog 文体(です・ます・説明体)**完全不同体系**,
     prompt 互不复用,blog 只用 gp blog 的规则文件与 examples-gold。
